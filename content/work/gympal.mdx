## Problem

Calisthenics progress is not a workout log. A log records what you did today.
Calisthenics progress is a ladder you move up slowly, where the same movement
has three or four harder versions and you might spend two months on one rung
before it earns the next. An app that stores completed sessions has no way to
represent that, so the thing you actually care about is not in it anywhere.

Access compounds it. Most of this training happens in a basement, a yard or a
corridor, which is exactly where there is no signal. An app that needs a
connection to record a set is an app that loses the set.

## Process

The data model is the programme, not the session. A routine holds a progression
ladder and where you currently sit on it, so the log becomes evidence of the
move rather than the thing being recorded.

Making it installable and offline-capable is the other half. Once it runs from
the device, a set recorded in a basement with no signal has to survive being
closed, and the app has to be openable without a network request at all, which
is why it is a progressive web app with a service worker rather than a wrapper.

Deliberately minimal and dark themed, because it is opened in a dim room
between sets.
